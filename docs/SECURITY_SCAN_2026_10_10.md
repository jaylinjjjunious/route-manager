# Security Cloud remediation

## Security scan hardening — 2026-10-10

The completed Security Cloud scan of main 02fb4436 reported 13 findings (10 medium, 3 low). Hardening is isolated on codex/security-scan-hardening; the native iOS draft remains separate. Current implementation:

- Authenticate Express application requests before parsing their bodies. Default JSON 128 KiB; owner-approved probation records 3 MiB, OCR 6 MiB, and existing batch-sync/preview routes 15 MiB. URL-encoded input is flat, 32 KiB, at most 50 fields. BlueAI retains its dedicated machine authentication/parser.
- Admit AI/TTS/OCR/preview, transit, proof uploads and probation writes through per-account minute, month and concurrency limits. Production admission uses service-role-only security_budget events in the existing Supabase activity_log; missing/unavailable accounting fails closed. Local files are development fallback only. Quota rows contain no prompts, image bytes or precise locations. Admission is serialized for the current single Express process; an atomic database RPC is required before adding replicas.
- Monthly account caps: AI 600 shared across AI routes; transit 500; uploads 100; probation write requests 200. Global monthly caps: AI 2,000; transit 1,500; proof/probation admissions 2,000 each. Minute caps are 10/3/3/10 respectively. AI/proof global concurrency is 2; transit/probation is 4, with tighter account concurrency (AI/transit 2; proof/probation 1). Transit permits the Tools screen’s simultaneous stops and alerts requests. These count admitted requests, including cache hits or subsequent invalid input. Aborted responses retain their concurrency slot for at most two minutes so unfinished provider work cannot bypass the limit or permanently exhaust it.
- Proof uploads allow one 5 MiB JPEG/PNG/WebP; verify signatures, decoded format, one frame, at most 12 million pixels, independently read the required UPC from the photo, and re-encode JPEG without source metadata. Saved proofs are verified only after this check. Serialize file/index commits; reject at 50 records/owner, 200 total records or 512 MiB image directory. Preserve history and existing orphans; do not evict another owner. Roll back a newly written file if its index commit fails. Corrupt metadata cannot be overwritten.
- Proof images require bearer authentication plus exact owner/index matching. No public static proof directory. The client loads approved same-origin image paths into revocable authenticated blob URLs; tokens never enter URLs.
- Transit trip keys include owner plus exact coordinates; alerts/network keys include location. Network discovery respects fresh TTL. Cache clearing is admin-only. Existing global provider limits remain.
- Probation writes are limited to the current UTC month and previous 23 months, at most 24 permanent records/account and 200 probation audit rows/month. Historical rows are preserved. Owner-request serialization bounds races on the single deployed process. Automatic archival, semantic audit coalescing and multi-replica database quotas remain future work.
- Worker singleton habits/proof/safety-news APIs return 410 before handlers, database access or body parsing. Unattributed D1 records are preserved pending an authenticated owner-confirmed migration. Worker deployment is not established by a Render deployment.
- Production public-workspace bypass is disabled in code and Blueprint. Scan sessions/photos and assistant conversations use owner-scoped browser keys; legacy unowned keys remain untouched and are never silently imported. The application remounts on account changes; stale assistant callbacks cannot write to another owner. Other legacy browser data still needs a separate ownership migration.
- Apple workflow installs locked dependencies before invoking the local Capacitor executable. Image/upload/iOS packages receive advisory patches. Additional dependency-advisory status and deployment verification are recorded below as checks finish.
